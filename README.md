## 挑 Ubuntu VPS，先核对这四件事

Ubuntu VPS 之间的真实差距，往往藏在配置表之外。同样一句“支持 Ubuntu 22.04”，有的商家给的是几分钟可用的干净最小镜像，有的塞满自家监控代理和过期软件包，内核停在两三年前。下单前建议按这个顺序过一遍：

1. **虚拟化类型必须是 KVM。** OpenVZ 共享宿主机内核，装不了 Docker，用不了 WireGuard，也改不了 sysctl 参数。只要计划里有容器或自定义内核参数，KVM 是硬门槛。
2. **镜像里有没有新版 LTS。** 一个内核还停在 2022 年的"Ubuntu 22.04 镜像"技术上没错，但你拿到手的补丁水平完全是另一回事。
3. **存储类型。** 机械盘基本退出主流之后，要分清商家写的是 SSD（多为 SATA）还是 NVMe。数据库和高并发应用对随机读写敏感，两种盘的差距实打实。
4. **续费价。** 不少商家靠首年低价拉新，续费时跳一档。判断长期成本，永远看第二年的价格。

## Ubuntu 22.04 还是 24.04？

新部署一律选 24.04 LTS，除非你有明确的兼容性理由留在 22.04。两个版本都还在支持期内，差距主要在剩余支持时间和软件版本：

| 项目 | Ubuntu 22.04 LTS | Ubuntu 24.04 LTS |
| --- | --- | --- |
| 标准支持到 | 2027 年 4 月 | 2029 年 4 月 |
| 内核 | 5.15（HWE 可到 6.5） | 6.8 |
| PHP / Python | 8.1 / 3.10 | 8.3 / 3.12 |
| 空闲内存占用 | 约 265 MB | 约 310 MB |

22.04 的标准支持在 2027 年 4 月结束。如果服务打算一跑两三年，从 24.04 起步能省掉一次大版本迁移——`do-release-upgrade` 的可靠性这些年确实有进步，但生产环境能不折腾就不折腾。

空闲内存那一栏值得多看一眼：24.04 只比 22.04 多占 45MB 左右，标准支持期却多了两年半，版本选择的账其实在这里。

RackNerd 的模板列表包含 22.04 和 24.04 的 LTS 镜像。以后需要模板之外的版本，KVM 套餐支持通过工单挂载自定义 ISO，用官方原版镜像自己装——这也是 KVM 相对 OpenVZ 的实际好处之一。

## 1GB 套餐跑 Ubuntu 够不够用？

轻量服务够用，但余量很小，这一点要有预期。有测评在 1GB VPS 上反复重启取过平均值：Debian 12 最小安装空闲占约 128MB，Ubuntu 22.04 约 265MB，24.04 约 310MB。也就是说，Ubuntu 装完什么应用都不跑，先吃掉接近三分之一的内存。

多出来的开销去向很具体：snapd 和它的服务常驻 80–120MB，哪怕一个 snap 包都没装；unattended-upgrades 和 apt 定时任务平时占 15–30MB，每天两次的更新检查还会造成内存尖峰；再加上 multipathd 这类在 VPS 上根本用不到的服务。打算用 1GB 套餐的话，装完系统先做一件事：`apt purge snapd` 卸掉用不上的 snap，能立刻回收上百 MB。

实际结论：1GB 跑 Nginx 静态站、反代或单个轻量应用没问题；上 MariaDB 这类数据库，内存很快吃紧。要跑数据库或 Docker，从 2.5GB 起步踏实得多——差价一年 13.5 美元，比半夜排查 OOM 划算。
